# Recipes

Use the invocation form supported by your client. The examples below use Codex's explicit
`$product` form.

## Turn a rough idea into a validated problem

Use when: you have a product idea but haven't confirmed the problem is real or worth solving.

```text
Use $product to pressure-test this idea: [idea]. Frame the problem, map it to an opportunity
solution tree, and tell me what to validate before building anything.
```

## Write a PRD for a SaaS feature

Use when: the problem is validated and you need a spec design and engineering can build from.

```text
Use $product to write a full PRD for [feature] in our SaaS app — scope, acceptance criteria,
success metrics, and a handoff for design and architecture.
```

## Define acceptance criteria for an AI/agentic feature

Use when: the product's core behavior comes from a model, so "acceptance criteria" means an eval set.

```text
Use $product to define acceptance criteria for our AI support agent: the task set, the pass
threshold, the human-in-the-loop level, and the non-determinism/latency/cost risks.
```

## Prioritize a backlog and build an outcome roadmap

Use when: you have a list of candidate work and need a defensible sequence.

```text
Use $product to prioritize this backlog [items] — run every applicable framework, show me where
they disagree, and turn the result into a Now/Next/Later outcome roadmap.
```

## Build a metric tree from a north-star metric

Use when: you have a north-star but no decomposition into the levers teams can actually move.

```text
Use $product to decompose our north-star metric [metric] into an input/driver metric tree with
guardrails and counter-metrics.
```
